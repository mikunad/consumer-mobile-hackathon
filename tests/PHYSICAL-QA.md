# Operator gate: R1–R5

Status: **blocked**. This checklist is not execution evidence. It requires the release gate, explicit permission to use dedicated QA devices/accounts, and the exact signed release candidate. Never use personal message history or reinstall a phone without approval. Do not automate Messages sends.

Before starting, record candidate SHA, backend source/config/schema/deployment identifiers, host and extension bundle/version/build, signed artifact SHA-256, distribution channel, device pseudonyms/OS, operator, approved policy version and UTC start time. Verify all three devices have that exact host and embedded extension. A simulator or host-only provider run cannot satisfy this gate.

Use Cora/creator, Finn/friend, Sage/subject in `CalledIt QA <runId>`; Oli is an outsider in a different synthetic conversation. Inventory all QA participants before any send. Use only approved synthetic numbers/accounts and harmless questions with distinct private sentinels in the question, choices, context and proof. Record device-local conversation keys as pseudonyms, not personal identifiers. Do not collect phone numbers, real sessions or OTPs in evidence.

1. **R1:** Verify host sign-in is shared with the extension. Human-send the first neutral card; record cold and warm open-to-send duration independently, with warm send ≤60 seconds. Open it on all three phones; record the same authoritative group/board and a persisted friend pick in <10 seconds. Sign-out/unauthenticated opens must reveal nothing. Record failure, not a screenshot-only pass, if any assertion is unmet.
2. **R2:** Before reveal inspect the subject’s actual transcript, static image, notification, VoiceOver, app-switcher snapshot, offline/restart and extension accessibility state. None may contain question/choices/context/proof or credentials. Rubbing cannot expose a server-redacted question. Finn must see authorized content. Verify exactly one server-authorized reveal and a fresh state after suspension; device clock changes must neither reveal early nor hold the reveal indefinitely.
3. **R3:** Human-forward original/update/board/result cards to Oli’s separate QA conversation. Verify no unauthorized room content or backend admission, neutral app-absent fallback, and no accidental last-room mapping. Record the approved board metadata disclosure rule and compare actual static pixels. Exercise account switch and explicit relink. A shared locator is not consent or authorization.
4. **R4:** Veto while locked and leave must quietly invalidate old opens, without a veto/actor broadcast. Verify approved answer/challenge/timeout/finalization behavior using exact rule version. Human-send a result using the correct bet/session; all three recipients must see the correct result. Record update placement, cancellation behavior, and the selected-A/navigate-to-B case. Draft insertion is not delivery, and APNs is not a transcript update.
5. **R5:** Record the actual unsupported/SMS rendering and install path for the distributed binary. From an app-absent QA device, receive a neutral card, install via the approved external channel, authenticate once and return to the original bet. Record any manual original-card reopen separately. Automatic return cannot pass on a manually reopened path, and an Expo host launch cannot prove extension inclusion.

For each assertion attach the synthetic screenshot/accessibility/payload/backend-state reference that proves it, device/OS, start/end, and an operator-signed result. Keep `blocked`, `failing`, and `passing` distinct. Missing provider/device/install capability is blocked. Do not upload or publish proof automatically. A code/backend/build change invalidates prior candidate proof.
