# Bounded remote enforcement probe

This operator entry is only for the reviewed `mobile.build` remote workspace route on one fresh private Revyl VM. It is not a generic local/paired-Mac launcher. The parent stages a new single-use nonce, exact version-2 launch proof, source/configuration seal and reviewed authority, then independently retains the actual returned build/operation IDs. No future ID, previous boot or caller exclusivity boolean is accepted as evidence.

The source archive must contain the real native source, simulator-provisioner sources/profile, `control-sockets.c`, this entry, `probe-config.json` and `launch-proof/{source-manifest,launch-plan,context,authority}.json`. The sealed configuration supplies the actual run/nonce, source revisions, fixture identifier and configuration version. The manifest must hash every source/configuration input, including this entry, the root bootstrap closure and inspector; the fixed vsock profile belongs in `configurationFiles`. Native compilation uses a separate private copy so generated plists cannot change the sealed original inputs.

The actual reviewed tool command invokes `python3 -E -s tests/mac-enforcement/enforcement-entry.py --launch-nonce <actual nonce> --source-manifest-sha256 <actual raw hash>` with an explicit clean environment. It builds an unsigned real app only as an evidence carrier, records candidate actual ancestor PIDs and the boot/source/nonce chain, then invokes the bounded enforcement-only/restoration probe exactly once. Candidates are not admission: root independently re-derives the actual agent identity and SDK-typed connected vsock8080 host endpoints and matches the kernel table. It creates no simulator and executes no native tests. Native/backend build-record paths are explicitly unused in this enforcement-only mode, not fabricated build evidence.

The fixed profile has zero external IP allow rules and no TCP fallback. Provider vsock is the intentional management channel, not proof against arbitrary non-IP/covert channels. Root checks the fresh sealed private helper/profile/agent/PID/birth/endpoints across the enforced interval; missing sockets, unsupported PF/kernel/broker behavior, unproven restoration or any admission mismatch fails the job. A timeout waits only for the independent watchdog's cleanup record; it never force-disables PF, flushes global state or broadens rules.

Every2s the operator emits and flushes a nonce/sequence/time-tagged stdout record before atomically writing its same-run local pulse. The local file is liveness only, never external-delivery authority. Even after local gates pass, the artifact/verdict remains `local-gates-pass-parent-tool-continuity-pending`. The trusted parent must make live log calls during the bounded probe and record each actual response with independently sampled parent call-start/return times, outside the guest. Retain those observations, the complete final tool logs and actual returned build ID independently of the archive; provider-prefix timestamp strings alone are not receipt authority. Then run `verify-tool-record.py --actual-tool-logs <actual JSON> --actual-parent-observations <actual timed calls JSON> --expected-build-id <returned ID> --run-id <actual run> --launch-nonce <actual nonce> --output <fresh file>` locally. It requires progressing promptly received actual tool pulses over the root-observed UTC enforcement window, exact emitted record hashes, chronological source output and completed denial/restoration. This compares trusted parent receipt clocks with the root guest's reported UTC window, not cryptographic time attestation. Synthetic fixtures are design checks only; the offline parser is not a signature verifier, live runtime authority or substitute for actual tool calls.

After local success, `out/CalledItMessages.app/QAEnforcementProbeEvidence` contains the actual owned records, pending independent parent continuity. This is a private unsigned artifact carrier, not an RC, native UI/provider/signing/distribution proof or full-V0 verdict. On failure, inspect the retained structured tool logs and stop/replan; do not retry with invented provenance or broader exceptions.

`inspect-control.py --nonce <fresh UUIDv4>` is a separate read-only diagnostic after the actual TCP-controller preflight found no eligible socket. It uses the real macOS SDK/libproc to inspect only current ancestor socket families, states and nonsecret VM socket endpoints, records executable hashes/current boot and optionally reads the kernel's vsock table. It does not call the provisioner or PF, create a simulator, send a packet, change a policy or approve a different control profile. `QAControlInspectionEvidence` holds observations only; a later isolation design must be reviewed against the actual result.
